# docXform — Product context

## Product purpose

Browser-native document conversion and PDF/Office utilities. Processing runs via WebAssembly in the user's tab; files are not uploaded to docXform servers.

## Users

- Professionals handling contracts, HR, legal, or health-adjacent documents
- Privacy-conscious individuals who avoid cloud converters
- Developers who verify behavior via DevTools network tab

## Register

**Brand** on marketing pages (home, articles, about, FAQ). **Product** on converter and tool workspace surfaces.

## Brand adjectives

Calm, credible, local, precise.

## Anti-references

Generic AI SaaS (purple gradients, glass cards, hero metric blocks, identical icon grids), upload-based converter sites, crypto-neon dark themes.

## Strategic principles

1. Show the privacy story with mechanism (WASM, zero upload), not fear marketing.
2. One primary action per screen: convert or pick a tool.
3. Typography and layout carry brand; color stays restrained.

## Primary CTA

Drop or open a file to convert (Word ↔ PDF first for new visitors).
